## 核心业务规则

### 返修

1. 采购选择“返修”后，需要维护返修方案、返修数量、预估运费、运费承担方和返修费。
2. 返修成本比较值 = 返修费 + 公司承担的预估运费。
3. 若采购总成本大于 1000，比较值占总成本达到 80% 时触发二次确认。
4. 若采购总成本小于等于 1000，比较值占总成本达到 60% 时触发二次确认。
5. 返修方案为“返修换货”时，必须维护更换后 SKU 和数量，并展示换货 SKU 单价、换货 SKU 金额。
6. 其他最终费用或结算信息在返修出库页面维护，不在次品处理池发起返修弹窗中展示。

### 报损

1. 采购选择“报损”后，不展示返修方案。
2. 确认报损方案后生成报损出库单，并进入报损审核流。
3. 报损审核通过后流转到仓库作业，仓库拣货后报废出库。

### 次品框归集

1. 次品框归集数据同样进入次品处理池。
2. 采购对次品框归集数据只能选择“报损 / 抵扣账单 / 赔款”。
3. 选择“赔款”时，需要维护赔款金额、流水、赔款方式（支付宝转账、银行卡转账）、赔款状态（部分、全部）、实际退款金额和凭证。
4. 实际退款金额由赔款金额合计自动得出。
5. 选择“抵扣账单”时，需要维护抵扣金额；抵扣供应商由系统按当前记录自动带出，不支持编辑。
6. 数据通过“次品存放类型”与已上架次品区数据区分，但数量字段统一为“待处理数量”。

## 交互状态

| 状态 | 页面反馈 |
|---|---|
| 默认列表 | 展示供应商、SKU、仓库、次品存放类型、待处理数量、采购成本金额、历史处理和更新时间 |
| 配置规则 | 条件组支持 SKU、平台、单价区间、货值区间；组内全部满足，组间 OR 命中 |
| 返修入库 | 展示返修数量、费用字段和成本测算 |
| 返修换货 | 展示换货 SKU 明细列表，输入数量后自动更新换货金额 |
| 报损 | 隐藏返修方案，只展示报损出库说明 |
| 抵扣账单 | 次品框归集选择抵扣账单后，展示抵扣金额和自动带出的抵扣供应商 |
| 赔款 | 次品框归集选择赔款后，展示赔款金额、流水、赔款方式、赔款状态、实际退款金额和凭证上传 |
| 已处理 | 通过独立 Tab 查看所有已发起处置记录，包含记录号、方案、数量、关联单据和状态 |
| 高成本返修 | 二次确认弹窗支持取消、确认返修、改为报损 |
| 筛选无结果 | 展示空状态 |

## 原型交付约束

- 原型类型：`prototype-draft`
- 交付形式：HTML 可交互原型
- UI 基线：Ant Design B 端后台样式，简洁、清晰、表单和表格优先
- 本轮发布范围：次品处理池根页面

## v2 UI 设计契约

- 视觉基线：`shared-references/ant-design-ui-guidelines.md`，采用 Ant Design 中文 B 端 ERP 风格。
- 壳层映射：`ErpShell / PageHeaderBar / QueryFilterBar / DataTablePanel / DetailDrawer / CreateModal / RiskConfirm`。
- 页面主任务：采购在当前上下文内查看次品、筛选、发起处理方案并追踪已处理记录。
- 交互约束：详情使用抽屉，方案使用弹窗，筛选使用自定义 Select，删除/高风险动作保留二次确认。
- 状态覆盖：待处理、已处理、筛选无结果、加载反馈、方案确认、保存成功反馈。
- 禁止项：不提供角色切换、状态切换、调试面板或悬浮演示控制；所有颜色和间距使用中央 token。
