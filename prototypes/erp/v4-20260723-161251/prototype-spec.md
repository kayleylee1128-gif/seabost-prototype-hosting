# 次品处理池原型说明

## 本轮调整范围

| 页面 | 调整内容 |
|---|---|
| 次品处理池主列表 | 使用“次品存放类型”区分已上架次品区和次品框归集；数量统一展示为“待处理数量”，不再拆分上架数量和暂存数量 |
| 次品处理池主列表字段 | 去掉“最近处理方案”，新增“更新时间”和“次品图片”；图片列打开当前 SKU 对应退件单的仓库上传图片，支持左右切换 |
| 次品处理池主列表排序与批量操作 | 待处理记录默认按供应商升序展示；新增行勾选、当前可见数据全选、已选数量提示和“批量设置方案”；批量操作需选择相同次品存放类型，避免混用两套业务规则 |
| 批量方案弹窗 UI | 统一采用信息摘要卡、方案分段控件、分区表格和风险提示，优化层级、间距、表格密度和操作按钮状态 |
| 次品处理池 Tab | 新增“已处理”Tab，查看所有已发起次品处置方案的记录数据，不展示平台字段 |
| 次品处理配置 | 条件组不再提供“库存类型”和“货值区间”条件；支持 SKU、平台、过去 X 天销量、单价区间；新增应用仓库；条件组样式为 Ant Design 风格卡片，组内 AND、组间 OR |
| 次品待处理详情 | 去掉“基础信息”；“退件单与库存来源”列表中的“上架时间”改为“收货时间”，新增“图片”列；点击图片可查看当前退件单上传的次品图片，保留采购成本摘要 |
| 设置处理方案弹窗 | 按 Ant Design 表单样式组织；供应商默认加载当前记录供应商，可切换 SKU 对应供应商；返修时默认带出供应商收件人、收件电话、收件人地址并支持编辑 |
| 返修方案 | 次品处理池发起返修时只保留“返修入库、返修换货” |
| 返修换货 | 展示换货 SKU 明细列表，支持输入换货 SKU 和换货数量，并展示换货 SKU 单价、换货 SKU 金额 |
| 报损 | 已上架次品区选择“报损”后，展示“报损 / 抵扣账单 / 赔款”二级方案；其中“报损”表示无挽损，直接生成报损出库单 |
| 历史处理 | 保留 SKU 历史处理次数入口和处理记录抽屉，记录历次处理方案、数量、金额和关联单据 |

## 核心业务规则

### 返修

1. 采购选择“返修”后，需要维护返修方案、返修数量、预估运费、运费承担方和返修费。
2. 返修成本比较值 = 返修费 + 公司承担的预估运费。
3. 若采购总成本大于 1000，比较值占总成本达到 80% 时触发二次确认。
4. 若采购总成本小于等于 1000，比较值占总成本达到 60% 时触发二次确认。
5. 返修方案为“返修换货”时，必须维护更换后 SKU 和数量，并展示换货 SKU 单价、换货 SKU 金额。
6. 其他最终费用或结算信息在返修出库页面维护，不在次品处理池发起返修弹窗中展示。

### 报损

1. 采购选择“报损”后，不展示返修方案。
2. 确认报损方案后生成报损出库单，并进入报损审核流。
3. 报损审核通过后流转到仓库作业，仓库拣货后报废出库。

### 次品框归集

1. 次品框归集数据同样进入次品处理池。
2. 采购对次品框归集数据只能选择“报损 / 抵扣账单 / 赔款”。
3. 选择“赔款”时，需要维护赔款金额、流水、赔款方式（支付宝转账、银行卡转账）、赔款状态（部分、全部）、实际退款金额和凭证。
4. 实际退款金额由赔款金额合计自动得出。
5. 选择“抵扣账单”时，需要维护抵扣金额；抵扣供应商由系统按当前记录自动带出，不支持编辑。
6. 数据通过“次品存放类型”与已上架次品区数据区分，但数量字段统一为“待处理数量”。

### 批量设置方案

1. 采购可在待处理列表勾选多条记录，点击“批量设置方案”统一设置处理方式。
2. 批量设置前必须选择相同的次品存放类型；已上架次品区按“返修 / 报损”选择，报损还需继续选择“报损 / 抵扣账单 / 赔款”；次品暂存区按“报损 / 抵扣账单 / 赔款”选择。
3. 批量选择“返修”时，弹窗补充返修入库 / 返修换货、返修数量、预估运费、运费承担方、返修费，以及每条记录对应的供应商收件人、收件电话和收件人地址；信息默认加载，可编辑。
4. 批量选择“报损”时，弹窗根据方案展示无挽损报损、抵扣账单或赔款信息；抵扣账单按供应商分组，每个供应商单独维护抵扣金额并实时汇总抵扣金额合计，按供应商生成对账明细；赔款按供应商卡片分组，每个供应商单独维护赔款金额、赔款流水、赔款方式、赔款状态和赔款凭证，实时汇总实际退款金额。
5. 批量设置仅统一处理方案，原记录的供应商、SKU、次品数量和来源信息保持不变；确认后清空当前勾选并反馈处理结果。

### 次品处理配置

1. 触发规则支持 SKU、平台、过去 X 天销量、单价区间；不提供库存类型和货值区间条件。过去 X 天销量可维护统计天数和销量阈值，命中规则为销量大于阈值。
2. 配置新增“应用仓库”，默认全部仓库，可选择具体仓库。
3. 已上架次品区选择“报损”后，必须继续选择“报损 / 抵扣账单 / 赔款”中的一个方案后才能确认。

### 次品图片

1. 主列表新增次品图片列，图片来源为当前 SKU 对应退件单的仓库上传图片。
2. 图片查看器展示退件单号、上传时间和图片说明，支持上一张、下一张和键盘左右方向键切换。
3. 次品待处理详情抽屉的“退件单与库存来源”列表新增“图片”列；点击当前行图片入口，打开该退件单上传的次品图片，并复用同一图片查看器。

## 交互状态

| 状态 | 页面反馈 |
|---|---|
| 默认列表 | 展示供应商、SKU、仓库、次品存放类型、待处理数量、采购成本金额、历史处理和更新时间 |
| 配置规则 | 条件组支持 SKU、平台、过去 X 天销量、单价区间，并可指定应用仓库；组内全部满足，组间 OR 命中 |
| 返修入库 | 展示返修数量、费用字段和供应商收件信息，不展示成本测算区 |
| 返修换货 | 展示换货 SKU 明细列表，输入数量后自动更新换货金额 |
| 报损 | 已上架次品区隐藏返修字段，展示“抵扣账单 / 赔款”二级方案；次品框归集保留直接结算方案 |
| 抵扣账单 | 次品框归集选择抵扣账单后，展示抵扣金额和自动带出的抵扣供应商 |
| 赔款 | 次品框归集选择赔款后，展示赔款金额、流水、赔款方式、赔款状态、实际退款金额和凭证上传 |
| 已处理 | 通过独立 Tab 查看所有已发起处置记录，包含记录号、方案、数量、关联单据和状态 |
| 高成本返修 | 二次确认弹窗支持取消、确认返修、改为报损 |
| 筛选无结果 | 展示空状态 |

## 原型交付约束

- 原型类型：`prototype-draft`
- 交付形式：HTML 可交互原型
- UI 基线：Ant Design B 端后台样式，简洁、清晰、表单和表格优先
- 本轮发布范围：次品处理池根页面

## v2 UI 设计契约

- 视觉基线：`shared-references/ant-design-ui-guidelines.md`，采用 Ant Design 中文 B 端 ERP 风格。
- 壳层映射：`ErpShell / PageHeaderBar / QueryFilterBar / DataTablePanel / DetailDrawer / CreateModal / RiskConfirm`。
- 页面主任务：采购在当前上下文内查看次品、筛选、发起处理方案并追踪已处理记录。
- 交互约束：详情使用抽屉，方案使用弹窗，筛选使用自定义 Select，删除/高风险动作保留二次确认。
- 状态覆盖：待处理、已处理、筛选无结果、加载反馈、方案确认、保存成功反馈。
- 禁止项：不提供角色切换、状态切换、调试面板或悬浮演示控制；所有颜色和间距使用中央 token。
